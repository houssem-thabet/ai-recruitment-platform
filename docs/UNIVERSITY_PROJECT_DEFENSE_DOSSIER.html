Project Objectives and Problem Statement

Traditional Applicant Tracking Systems (ATS) rely on rigid substring matching that penalizes qualified candidates for synonym variations (e.g., React.js vs. React, PostgreSQL vs. Postgres) while giving zero constructive feedback. Conversely, naive LLM-wrapper recruitment tools introduce three severe engineering hazards: hallucinated credentials, demographic bias & PII leakage, and total service outage when external cloud APIs rate-limit or fail.

1. Multi-Role SaaS Separation

Three strictly partitioned workspaces—Candidate Career Studio, Recruiter ATS Command, and Admin Governance Console—protected by Edge JWT verification and database-backed RBAC.

2. Hybrid Resilient AI Engine

Combines live structured LLM & dense embeddings (OpenAI, Anthropic, Gemini) with a 100% deterministic local NLP & Sublinear TF-IDF Vector Engine for zero-downtime offline execution.

3. Explainable Human-in-the-Loop Scoring

Decomposes every 0–100 compatibility score into 5 auditable dimensions with human rationales, recruiter score override, mandatory AI job-description approval, and non-decision interview note organization.

4. Mathematical Fairness & Vault Privacy

Strips demographic markers before vectorization, redacts PII before external API calls, isolates uploaded CVs outside public/, and enforces GDPR Right-to-Erasure cascade deletion.

08

Database Design, 3NF Normalization & Indexing

  • Third Normal Form (3NF): Repeating skills are normalized into canonical Skill, CandidateSkill, and JobSkill tables; employer metadata resides solely on Company without transitive duplication across Job rows.
  • Strategic JSONB Audit Columns: Used exclusively for versioned AI snapshots (CVAnalysis.extractedData, MatchResult.weightsUsed, InterviewEvaluation.evidenceMap, and Application.statusHistory).
  • GDPR Cascade vs. Audit Preservation: Personal records use ON DELETE CASCADE for complete erasure upon DELETE /api/auth/me, whereas AuditLog and AIUsageLog use ON DELETE SET NULL so anonymized security telemetry survives account deletion.
  • Composite B-Tree Indexes: Job(status, publishedAt), MatchResult(jobId, overallScore), and Interview(recruiterProfileId, scheduledAt) guarantee logarithmic query performance.

AI and Natural Language Processing (NLP) Algorithms

  • Binary Signature & Typographic Normalization (cv-parser.ts): Validates %PDF- and PK\x03\x04 headers, expands Unicode ligatures (ﬁ → fi, ﬂ → fl), removes soft hyphens, rejoins wrapped lines, and segments CVs into 9 bilingual (EN/FR) sections.
  • Interval-Union Experience Estimator (O(K log K)): Converts role date spans into integer month coordinates, sorts intervals, and merges overlapping jobs before dividing by 12—eliminating double-counting of concurrent freelance/full-time roles.
  • Anti-Hallucination Grounding Filter (filterGroundedItems): Discards any LLM-claimed skill or certification unless it is verified in our deterministic 50+ canonical skill taxonomy or appears verbatim in the raw CV text.
  • Sublinear TF-IDF & Anisotropy-Calibrated Dense Embeddings (semantic.ts): Dampens keyword stuffing via logarithmic term frequency and calibrates dense cosine similarity before hybrid convex fusion:
w(f, d) = (1 + ln(count(f, d))) × idf(f),   where idf = 2.10 (skill) | 1.65 (tech stem) | 1.35 (bigram) | 1.00 (unigram)
s_dense_cal = clamp_[0,1]( (cos(v_A, v_B) - 0.18) / 0.70 )
s_hybrid(A, B) = 0.68 · s_dense_cal + 0.32 · s_lexical_tfidf

Candidate–Job Matching Algorithm (Mathematical Specification)

Before scoring, both candidate and job texts pass through stripProtectedAttributes(), guaranteeing mathematical invariance to gender, age, nationality, religion, marital status, and disability. Recruiter weights W = (40, 25, 15, 15, 5) are normalized onto the 100-simplex:

1. S_skill (40%): round( min(100, (Σ transferCredit(r, C) / |R_J|) × 100 + 10 · |E_J ∩ S_C| / |E_J|) )
   • Exact canonical match = 1.00 | Ecosystem transferability (e.g., Vue.js → React, Docker → K8s) ∈ [0.35, 0.85]
2. S_exp (25%): round( 68 · min(1, y_cand / y_req) + 32 · min(1, 2.2 · s_hybrid(Exp_C, Role_J)) )
3. S_edu (15%): Ordinal degree rank ρ ∈ {0..4} alignment (68..95) + min(10, 5 × N_cert)
4. S_resp (15%): round( clamp_[20,100]( 205 · s_hybrid(Corpus_C, Responsibilities_J) ) )
5. S_lang ( 5%): round( 100 × |L_C ∩ L_J| / |L_J| )  [or 70 neutral verification flag if unspecified]

S_overall = round( (S_skill·ŵ_1 + S_exp·ŵ_2 + S_edu·ŵ_3 + S_resp·ŵ_4 + S_lang·ŵ_5) / 100 ) ∈ [0, 100]
Worked Defense Example: A candidate matching 4/5 required skills directly + Docker adjacent to Kubernetes (0.55 credit → S_skill = 91), 4/4 years experience (S_exp = 95), M.Sc. + 1 certification (S_edu = 100), project cosine 0.41 (S_resp = 84), and 2/2 languages (S_lang = 100) achieves round((91×40 + 95×25 + 100×15 + 84×15 + 100×5)/100) = 93/100, while flagging Kubernetes depth under verificationAreas for the human interviewer.

Security, Privacy & Governance Controls

Authentication & Session Hardening

bcryptjs (cost 10), unified 8–128 char complexity rule, SHA-256 single-use 1h reset tokens, Edge HS256 JWT + DB ACTIVE status re-verification on every API call.

Zero-Trust CV & Tenant Isolation

CVs stored in non-public storage/cvs/; recruiters can read/analyze a CV only after a verified company application; privateNotes and override notes never leak to candidates.

Input, URI & CSV Injection Defense

parseJsonBody blocks malformed JSON 500s; sanitizeHttpUrl & sanitizeLogoUrl block javascript: and SVG/HTML data URIs; escapeCsvCell neutralizes = + - @ formula payloads.

Ethical AI & Human Authority

No auto-rejection; mandatory human approval on AI job postings; explicit consent check before AI interview note organization; PII redaction prior to external LLM requests.

Oral Defense (Viva) Q&A Preparation Guide

Q1: What happens during the live defense if there is no OpenAI/Gemini API key or the internet drops?
TalentAI computes a complete deterministic NLP & Sublinear TF-IDF evaluation locally first. If no API key is configured or an external provider times out / returns HTTP 429 or 500, the engine falls back in 0 ms to DETERMINISTIC_NLP mode, logs the event in AIUsageLog, and badges the UI transparently.
Q2: How do you prevent an LLM from hallucinating skills or degrees on a candidate's CV?
Every LLM-extracted item is passed through filterGroundedItems(), which cross-checks the canonical skill against both our deterministic regex taxonomy detector and the lowercase raw CV text. Ungrounded items are discarded before database persistence, and candidates can manually inspect and correct extracted data.
Q3: Why use sublinear TF (1 + ln(tf)) and interval merging instead of standard keyword counts and summed job durations?
Linear term counts let candidates game cosine similarity via keyword stuffing; 1 + ln(tf) dampens repetition. Similarly, summing role durations double-counts overlapping freelance and full-time jobs; sorting and merging month intervals in O(K log K) measures true non-overlapping career duration.
Q4: How are confidential candidate CVs and internal recruiter notes protected against unauthorized access?
CV binaries are stored outside public/ in storage/cvs/ with magic-byte validation and UUID filenames. GET /api/candidates/cv/[id] verifies either candidate ownership or an active application to the recruiter's company (even administrators cannot browse private CVs), and all candidate-facing endpoints strip privateNotes and recruiterOverrideNote.
